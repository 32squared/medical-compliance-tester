# SKIX 2차 의료자문 — 시스템 준비 상태

작성일 2026-08-11 · 대상 브랜치 `claude/dazzling-shamir-097a67`

자문 당일 바로 진행할 수 있는 상태까지 무엇이 갖춰졌고 무엇이 남았는지 정리한다.
설계 내용은 [분과별 시나리오 및 평가 방안](advisory_specialty_scenarios.md), 렉스소프트 회신 요청은 [회신 요청](advisory_rexsoft_inquiry.md)에 있다.

---

## 1. 현재 상태

로컬 DB 실측 기준이다.

| 항목 | 수량 | 비고 |
|---|---|---|
| PHR 케이스 | 70 | 7개 분과 × 10명, 585행 원본에서 빌드 |
| 케이스 배정 | 70 | 분과별 10건씩 담당 자문위원 1인에게 |
| 자문위원 계정 | 7 | `rexsoft01`~`rexsoft07` |
| 고정 문항 | 48 | 6분과 × 6문항 + 응급의학 4문항 × Vital 3세트 |
| 저장된 판정 | 0 | 자문 시작 시점 |

문항 48건의 내역은 6분과 각 6문항(Q1~Q5 + 함정문항 H)과 응급의학 4문항(Q1·Q3·Q4·H)을 V-A/V-B/V-C 세 세트로 각각 실행하는 12건이다. 순환기 Q3은 V-B 한 세트만 쓴다.

## 2. 자문위원이 보는 화면

로그인하면 채팅 테스터 한 화면만 남는다. 상단 메뉴, 환경 선택, 엔드포인트 전환은 숨겨지고 엔드포인트는 SKIX로 고정된다. 자동 평가 결과(법률·문진·PHR 정합성)도 가려진다 — 시스템 점수를 먼저 보면 판정이 그쪽으로 끌려가기 때문이다.

화면에서 하는 일은 네 가지다.

1. **케이스 선택** — 자기에게 배정된 10명만 목록에 뜬다. 고르면 우측에 원본 검진 기록이 상시 표시되고, 상단에 페르소나(나이·성별·배경)가 나온다.
2. **문항 선택** — 그 케이스에 매인 고정 문항이 드롭다운에 뜬다. 고르면 질문이 입력창에 그대로 채워진다. 질문을 손으로 옮겨 적으면 문장이 조금씩 달라져 개선 전후 적정률 비교가 성립하지 않으므로, 예시 질문 버튼은 자문위원 화면에서 숨겼다.
3. **가상 Vital 선택** — 응급 문항을 고르면 그 문항이 지정한 세트로 자동 설정된다. 수동으로 바꿀 수도 있다. 세트를 바꾸면 새 대화로 시작한다(이전 세트 수치가 문맥에 남으면 어느 세트에 대한 답변인지 구분되지 않는다).
4. **판정** — 답변 아래 검토 카드에서 5항목을 `적정 / 부적정 / 해당없음`으로 판정하고, 부적정이면 사유와 수정안 문장을 남긴다. 저장한 판정은 대화를 다시 열면 그대로 불러와 수정할 수 있다.

상단 배지에 `배정 n · 질문 n · 검토 n`이 표시되고, 케이스 선택기에는 검토 완료 `✓`, 질문만 한 케이스 `·` 표시가 붙는다.

## 3. 가상 Vital 3세트

수치는 서버 상수가 소유한다(`proxy_server.py`의 `PHR_VITAL_SETS`). 클라이언트는 세트 키만 보내므로 자문위원마다 다른 값이 들어갈 수 없다.

| 세트 | 혈압 | 심박 | SpO2 | 해당 구간 |
|---|---|---|---|---|
| V-A | 158/96 | 92 | 97% | 고혈압 1기 상단 · 심박·산소포화도 정상 |
| V-B | 178/104 | 108 | 96% | 고혈압 2기 · 빈맥 |
| V-C | 205/118 | 122 | 93% | 고혈압 위기 기준 초과 · 산소포화도 94% 이하 |

주입 값에는 `가상 주입값`이라는 표시가 함께 들어가고, 어느 세트로 받은 답변인지는 대화에 기록된다.

**응급 문항의 질문 문장에는 혈압 수치를 적지 않는다.** 세 세트를 번갈아 주입하는데 문장에 숫자가 박혀 있으면 말한 수치와 주입된 수치가 어긋나, 시스템이 어느 쪽을 근거로 답했는지 구분되지 않는다.

## 4. 자문 산출물을 꺼내는 경로

관리 화면(`/phr`)에 자문 판정 집계가 있다. 항목별 적정·부적정·해당없음과 적정률(적정 / (적정 + 부적정), `해당없음`은 분모에서 제외)을 보여준다.

엑셀 내보내기는 세 시트로 나온다.

| 시트 | 내용 | 쓰임 |
|---|---|---|
| 01_판정원본 | 자문위원·분과·케이스·질문·답변 + 5항목 판정/사유/수정안 | 근거 보존 |
| 02_항목별집계 | 항목별 적정률 | 어느 항목에서 부적정이 몰리는지 |
| 03_부적정 | 부적정 건만 + 수정안 문장 + 분류 칸 | **채점 기준의 원재료** |

03 시트의 분류 칸에 누락형·단정형·오역형을 적어 넣으면, 누락형은 답변 생성 규칙으로, 단정형은 금지 표현 목록으로, 오역형은 라벨 사전으로 간다.

## 5. 남은 작업

### 5.1 사람이 해야 하는 것

**페르소나 나이·성별 입력 (70건).** 원본에 나이 필드가 없고 성별은 여성 대상 암검진 이력으로만 추정된다(31명은 그마저 불가). `/phr` 화면의 페르소나 버튼에서 채운다. 자문위원이 '그 사람'이 되어 질문하는 방식이라 비어 있으면 질문이 추상적으로 흐른다. 렉스소프트 회신(요청 2번)이 오면 실제 값으로 교체하고, 그 전에는 임의값을 넣고 임의값이라는 사실을 자문위원에게 명시한다.

**리허설.** 48건을 한 번씩 실행해 인용 수치 오류를 선수정한다. 사실이 틀린 답변으로 표현을 논의하면 1시간이 그대로 소모된다. 관리자 계정으로 케이스·문항을 골라 순서대로 실행하면 되고, 문항 선택기가 있으므로 타이핑은 필요 없다.

**자문위원 계정 안내.** `rexsoft01`~`rexsoft07`. 초기 비밀번호는 저장소에 적지 않고 자문위원에게 별도로 전달한다. 분과 배정은 `scripts/seed_advisory.py`의 `SPECIALTY_ADVISOR` 표에 있으며, 렉스소프트가 다른 배정을 주면 그 표만 고쳐 다시 실행하면 된다.

### 5.2 운영 반영

지금까지의 작업은 로컬 DB 기준이다. 운영에 올리려면 배포 후 같은 스크립트를 운영 DB 대상으로 한 번 실행해야 한다.

```bash
python scripts/seed_advisory.py --phr <70명.xlsx> --questions <체크케이스.xlsx>
```

같은 케이스 번호와 같은 문항 id는 덮어쓰므로 여러 번 돌려도 결과는 같다. 렉스소프트 회신으로 데이터가 바뀌면 파일만 갈아 끼우고 다시 실행한다.

### 5.3 구현하지 않은 것

**배치 실행으로는 PHR이 실리지 않는다.** `/api/test/batch`는 SKIX를 직접 호출하는 경로라 케이스를 붙이지 않는다. 리허설 48건은 채팅 테스터에서 한 건씩 실행해야 한다. 문항이 고정 40문항 규모라 일회성으로는 감당되지만, 회귀 검증을 반복하게 되면 배치 경로에 케이스를 관통시키는 작업이 필요하다.

**자동 평가의 보류 3축은 여전히 배점 0이다.** 판정 라벨 해석·역추정 절제·교차통합/프라이버시 세 축의 기준이 이번 자문의 산출물이므로, 자문이 끝나야 배점을 켤 수 있다. 현재 활성 3축 65점(인용 정확성 25 · 결측/이력 탐색 20 · 시점/추세 정합성 20)은 그대로 돌아간다.

## 6. 이번에 함께 고친 것

자문 준비와 별개로, 조사 중 확인된 결함 세 가지를 고쳤다.

- **문진 자동평가 누락** — PHR 케이스가 붙지 않은 대화에서 문진 품질 자동평가가 통째로 건너뛰어지고 있었다. PHR 평가 축을 넣을 때 삽입된 조기 반환이 원인이었다.
- **판정 조회 시 다른 자문위원 판정 노출** — 답변 id로 조회하면 검토자 조건이 무시돼 같은 답변에 대한 다른 자문위원의 판정까지 반환됐다.
- **연도 표기** — 엑셀이 연도를 실수로 주는 탓에 화면과 전달 데이터에 `2014.0`으로 나오던 것을 4자리로 정규화했다.
