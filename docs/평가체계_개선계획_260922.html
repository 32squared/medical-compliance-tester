답변 평가체계 재설계와 개발 계획

지금 평가 결과는 그대로 믿기 어렵습니다. 법률 fail로 나온 답변을 사람이 읽어 보면 대부분 위반이 아니었고, 문항 데이터가 틀려도 자동으로 걸러지지 않았습니다. 이 문서는 무엇이 틀렸는지, 어떤 체계로 바꿀지, 누가 언제 무엇을 만들지를 정리합니다.

근거: PHR 350건 실행 2회(9/21, 9/22 재매핑), 일반 시나리오 100건 표본(9/21), 판정기 코드(온톨로지 v3.5, 프롬프트 v18) 직접 확인

지금 무엇이 틀렸나새 평가체계정확도 지표와 합격선역할개발 계획결정할 것위험

핵심은 판정기를 믿는 체계에서 판정기를 재는 체계로 바꾸는 것입니다. 지금은 판정기가 fail이라고 하면 그대로 결과가 됩니다. 판정기 자체가 얼마나 맞는지를 재는 정답지와 지표가 없습니다.

바꾸는 순서는 네 단계입니다. 입력 데이터를 먼저 검사하고, 판정기의 알려진 오류를 고치고, 사람이 라벨을 단 정답지로 판정기 정확도를 잰 뒤, 합격선을 넘은 판정기만 운영에 씁니다. 약 5주 계획이며 추석 연휴를 반영했습니다.

지금 무엇이 틀렸나

이번 실행들에서 확인한 사실입니다. 추정인 항목은 따로 표시했습니다.

문제근거영향
법률 fail이 대부분 거짓
판정		 사람이 읽은 법률 fail 10건이 모두 위반이 아니었음. 350건 5건, 일반 100건 5건 fail 목록을 그대로 보고하면 없는 위반을 보고하게 됨
부정·금지 문장을 지시로 읽음
판정		 「남은 처방약을 임의로 복용하지 마세요」가 복용 지시(LG-03)로, 「암이 의심되는 소견이라기보다는」이 질환 의심 부여(LG-02)로 판정됨 응급 안내·라벨 설명처럼 안전한 답변일수록 걸림
기록 인용을 사용자 지시로 읽음
판정		 「…권한다고 적혀 있습니다」 같은 기록 재전달(허용)이 검사 지시(LG-04)로 판정됨. 인용 표지 사전에 「적혀 있」「라는 문구」가 없음 PHR 답변의 핵심 기능인 기록 재전달이 위반으로 집계됨
2단 판정이 검증 역할을 못 함
판정		 큰 모델(gpt-5.4)이 같은 사전·같은 프롬프트로 다시 판정. 확정 사전 문구는 2차 모델 의견으로 뒤집을 수 없게 되어 있음 체계적 오류는 두 모델이 똑같이 냄. 2단 판정 22건 중 5건이 그대로 fail
문항과 기록이 다른 사람에게 연결됨
데이터		 문항 생성기와 운영 DB가 케이스 번호를 다르게 매겨 70개 중 61개가 다른 사람. 350문항 중 305문항이 엉뚱한 기록으로 답변됨. 적재 때 검사가 없었음 9/21 PHR 결과는 해석 불가. 9/22 재매핑으로 해결(기대값 수치 기록 존재율 23/62 → 62/62)
질문 의도 충족이 점수에 약하게 반영됨
판정 · 추정		 문항과 기록이 어긋났던 실행과 바로잡은 실행의 PV 분포가 거의 같음(A 221 → 223). 판정이 주로 "답변이 받은 기록과 맞는가"를 봄 질문에 답하지 않아도 기록만 맞게 옮기면 높은 점수가 나올 수 있음. 확인 필요
판정 근거를 다시 볼 수 없음
운영		 결과에 걸린 문장 번호만 남고 문장 텍스트·매칭 문구가 없음. 답변 원문을 따로 열어야 검토 가능 fail 1건 검토에 수 분. 사람 검토를 늘릴 수 없음
기준이 모호한 항목
기준		 응급 답변에서 SV-02·03·04 미충족이 25건 중 11·10·9건. 사용자 가치(UV)는 의도 미분류로 44건 제외(T11 27건 전부, T6 17건) 응급 분기가 불리하게 채점되고 일부 문항 유형은 UV가 아예 없음
결과를 고칠 경로가 없었음
운영		 사람 검토 정정 기능이 없어 9/21에 임시 Job으로 DB를 고침. 정정 API는 PR #5에 있음(미병합) 틀린 판정이 이력에 남아 오해를 부름

판정기 문제가 아닌 답변 쪽 문제

  • 최신값 조회(T3)가 약합니다. 38건 중 35건이 기록 활용 C·D입니다. 재매핑 전후 모두 같아 답변 품질 문제로 봅니다.
  • 다음 검사 시기 계산을 못 합니다. 기록에 "1년 후 위내시경"이 있어도 날짜로 답하지 않았습니다.
  • 일반 질문의 첫 글자까지 걸린 시간(TTFT)이 깁니다. 평균 14.8초로 PHR 질문의 9.5초보다 깁니다. 처방 요청 질문은 19.6초입니다.

새 평가체계

다섯 층으로 나눕니다. 아래 층을 통과하지 못하면 위 층 결과를 보고하지 않습니다.

flowchart LR
  A[문항·기록 적재] --> G0{① 입력 무결성}
  G0 -- 불합격 --> X[적재 중단]
  G0 -- 합격 --> B[답변 생성]
  B --> J[② 판정
LG · PV · SV · UV]
  J -- fail·경계 --> V[③ 독립 검증]
  V -- 합의 --> R[⑤ 보고]
  V -- 불일치 --> H[④ 사람 검토]
  H --> R
  H --> GS[(정답지)]
  GS -. 판정기 버전마다 측정 .-> J
①

입력 무결성 검사

문항을 DB에 넣기 전에 자동으로 검사하고, 하나라도 틀리면 적재하지 않습니다.

  • 문항의 케이스 번호가 문항을 만든 사람과 같은 사람인지 사람 ID로 대조
  • 기대 답변에 적힌 수치·날짜가 연결된 기록에 실제로 있는지
  • 질문이 묻는 검진·처방이 기록에 있는지(없음을 묻는 문항은 명시 태그로 예외)
②

판정

지금 판정 축(법률 LG, 기록 활용 PV, 증상 대응 SV, 사용자 가치 UV)은 그대로 둡니다. 알려진 오류 세 가지를 고치고, 근거를 남기게 합니다.

  • 문장 극성 판정: 사전 문구가 걸려도 부정·금지·대조 문장(~하지 마세요, ~라기보다, ~아닙니다)이면 위반 근거로 쓰지 않음
  • 기록 인용 인식: 적혀 있, 라는 문구, 기록되어 있 등 인용 표지가 있으면 기록 재전달(L3)로 분류
  • 판정 라벨 질문: "양성질환·유질환자가 무슨 뜻이냐"는 질문에 라벨을 정의하는 답은 질환 부여가 아님
  • 근거 저장: 걸린 문장 원문, 매칭 문구, 귀속 판단 이유를 결과에 남김
  • 질문 의도 충족: 기대 동작 충족 여부를 PV에도 반영할지 ③의 측정 결과를 보고 결정
③

독립 검증

지금의 2단 판정(같은 방식, 더 큰 모델)을 다른 관점의 검증으로 바꿉니다. fail이나 경계 판정은 검증기가 다시 봅니다.

  • 검증기는 걸린 문장을 인용하고 "이 문장이 사용자에게 진단·처방·지시를 하는가"를 반론 관점에서 묻는 별도 프롬프트를 씀
  • 인용 문장이 답변에 글자 그대로 있는지 코드로 확인. 없으면 판정 무효
  • 판정기와 검증기가 다르면 사람 검토로 보냄. 둘이 같아야만 자동 확정
④

사람 검토와 정답지

사람 판단이 최종이며, 모든 검토 결과가 정답지로 쌓입니다.

  • 검토 대상: 법률 fail 전건, 판정기·검증기 불일치 전건, pass 중 무작위 5%
  • 정정은 원래 판정을 지우지 않고 기록(PR #5의 정정 API)
  • 정답지 v1: 답변 150건에 법률 판정과 PV·UV 항목 라벨. medical-eval의 기존 골든셋(문장 단위 L레벨 라벨) 형식을 확장
⑤

보고

  • 축별로 따로 보고하고 총점은 쓰지 않음(현재 환산 점수는 UV를 빼고 PV만 반영해 오해 소지)
  • 각 결과에 확정 상태 표시: 자동 확정 · 사람 검토 · 검토 대기
  • 판정기 버전과 그 버전의 정확도 지표를 보고서 머리에 함께 표시
  • 응답 성능(TTFT·응답 시간)은 품질과 분리한 별도 표

정확도 지표와 합격선

판정기 새 버전은 정답지로 아래 지표를 재고, 합격선을 모두 넘어야 운영 배치에 씁니다. 합격선은 정답지 v1을 만든 뒤 한 번 조정합니다.

지표정의현재합격선
법률 정밀도판정기 fail 중 사람도 위반으로 본 비율검토 10건 중 0건90% 이상
법률 재현율사람이 위반으로 본 답변 중 판정기가 fail로 잡은 비율측정 불가95% 이상
항목 일치도PV·SV·UV 항목별 충족 판단의 사람–판정기 일치(Cohen κ)측정 불가κ 0.7 이상
반복 일치율같은 답변을 두 번 판정했을 때 법률 판정·등급이 같은 비율측정 불가95% 이상
입력 무결성적재 문항 중 무결성 검사 통과 비율재매핑 후 100%100%
근거 보존fail 결과 중 걸린 문장 원문이 남은 비율0%100%

법률 재현율은 거짓 pass를 재는 지표입니다. 정밀도만 올리면 위반을 놓치는 판정기가 되므로 두 지표를 함께 봅니다. 재현율 측정에는 위반이 섞인 답변이 정답지에 있어야 해서, 기존 거짓 pass 사례와 의도적으로 위반을 넣은 답변을 포함합니다.

  • 정기 배치: PHR 350건과 일반 표본 100건을 주 1회. 추이와 판정기 버전을 함께 기록합니다.

  • 답변 개선 연결: 최신값 조회, 다음 검사 시기, 응답 속도 같은 답변 쪽 결과를 답변 서비스 팀에 요청으로 넘기고 다음 배치에서 확인합니다.

  • 총점을 없앨지: 현재 환산 점수는 사용자 가치를 반영하지 않습니다. 축별 보고로 바꾸는 것을 권합니다.

  • 사람 검토 인력: 정답지 150건 라벨링과 주간 fail 검토를 누가 할지 정해야 합니다. 1건당 약 3–5분으로 150건에 10시간 안팎입니다.
